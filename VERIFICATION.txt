KikiShield 0.6.1 — verification

RESULTS
187/187 Node.js regression tests passed (Node v24.19.0), including all 116
previous regressions and 71 new Activity/automation/independent-review cases.
19/19 Node LinkeDOM interface regression groups passed: 6 new layout,
accessibility and navigation contracts, 9 retained unread-count cases and
4 retained Activity/automation interface regression groups.
Syntax and whitespace checks passed. No new remote runtime dependencies.

Historical 0.4.0 results, NOT re-run for 0.6.1:
44/44 Chromium interface fixture checks; 16/16 Chromium R132 rendering/CORS checks.
That browser was Chromium 133.0.6943.0 with headless software WebGL2.
The 0.6.1 interface was checked using a DOM simulation, not a browser layout engine.
LinkeDOM does not render pixels or measure layout. Panel-size tests inspect explicit
sizing instructions at four viewport sizes, not actual browser-rendered geometry.
The cloud browser does not permit opening the local HTML visual fixture.

This is fixture-based verification, not live certification of a full addon pack.
No game login, real target player or live interaction was used.
Firefox Android and actual userscript-manager installation remain untested.

SECURITY / COMPATIBILITY

New in 0.6.1:
- Consistent 44 px actions, minimum 64 px setting rows, 18 px outline icons and
  shared gutters; descriptions may increase row height when they wrap.
- Three equal icon-and-label tabs, grouped setting cards, collapsed secondary help
  and an Activity toolbar with equally sized icon actions and explicit names.
- Stable 380 by 600 px shell clamped to the viewport, with a scrolling tab body.
  Source sizing instructions cover 1100x760, 390x844, 320x568 and 844x390.
- DOM contracts verify accessible names and help references, decorative local SVGs,
  a labelled panel per tab, click/keyboard navigation, all retained settings and
  primary controls available outside collapsed help.
- Protection, automation, Panic and unread behavior remain covered by existing
  regressions. This release changes the interface, not the incoming-action policy.

Retained from 0.6.0:
- Three compact tabs preserve existing access, addon, automation and Activity
  controls; the counter is separate from the retained-event/session totals.
- Grouped repeat events increment unread; 150 events display 99+ while the
  internal count remains accurate. Reading Activity keeps records intact.
- Protection/Automation do not mark Activity read; closed panels, hidden browser
  tabs and Panic retain unread. Visibility restoration acknowledges rendered rows.
- Read acknowledgement happens after Activity render, so closing the panel before
  the deferred paint cannot silently consume an unseen notification.
- Viewing Activity marks the whole journal read, including under a severity filter.
- Clearing the log and changing accounts reset unread without changing protection.
- One 150 ms refresh per burst; no new network calls or polling interval.
- Independent source review confirmed no ingress/safety blockers in this change.

New in 0.5.0:
- Expandable immutable command snapshots, severity and independently assessed
  direct operations; routine addon metadata is not a violation accusation.
- Actual native R132 list updater and its relation triggers tested: blacklist,
  ghost plus blacklist, whitelist removal, persistence calls and guarded undo.
- Undo preserves a pre-existing blacklist or whitelist and refuses changed state.
- Off-by-default automation, configurable serious-event threshold and explicit
  BCC/LSCG presence rules; trusted people and strict member-ID exceptions.
- Outer server sender identity only; no nested-ID redirection or self-punishment.
- Unchanged native appearance/items, relationship synchronization and full room
  snapshots cannot falsely trigger automatic violation enforcement.
- A BCC relay's target is its subject, not the recipient: relays to third parties
  still receive serious assessment. Caster/role assessment uses real compressed
  BCC settings; missing settings remain uncertain rather than incriminating.
- Account/room/setting changes, Panic, lost connection and malformed trust data
  cancel or skip queued actions; native API failures cannot stop unrelated traffic.
- Five automatic changes per minute and fifty per session; no deferred ban batch.
- 64 KiB per payload, 1 MiB total, 100 records; bounded primitive target labels;
  distinct commands remain distinct and ordinary chat/Panic content is omitted.
- Tracked Map tests verify Clear/eviction do not retain private payload references
  through the automation queue/history. Clear cancels pending automatic actions.
- DOM tests verify inert hostile payload text, disclosure/filter/scroll state,
  strict exceptions input, native-action controls, Undo and numeric target zero.

New in 0.4.0:
- Separate BCC/LSCG defaults, migration and core checks when isolation is OFF.
- Panic blocks before listeners and disconnected buffers, keeps account/room
  lifecycle, denies trusted incoming changes, and sends no activation announcement.
- Native audio hooks preserve return contracts, pass through when inactive,
  avoid retry storms on failure, and restore known media mute state.
- BCC malformed outfit/gift/room/speech validation and actual ingress rejection.
- Bounded decoder crosschecked against real BC LZString on 107 string fixtures,
  including UTF16 and exact size caps; oversized expansion rejected during decode.
- BCC custom activity signatures isolated without confusing ordinary BC activity
  or normal text mentioning their names.

- All six native interaction levels, owner/lover/whitelist/dominance, revocation,
  sender-versus-recipient lists, blacklist/ghostlist precedence and extra modes.
- BCC recipient-only Friend/Whitelist/Lover/Owner roles; defaults and mixed effects;
  corrupt own settings; real BC LZString decoding in the active-control test.
- A normally permitted non-caster cannot send active AnimaFurta commands, while
  the actual permitted caster reaches the real upstream handler.
- BCC changeAppearance/publishAction relays and unverified controller claims stop.
  A local cast grants a claim only to its target and room; ghosted targets stop.
- BCC and LSCG metadata passes in compatibility mode; selected isolation blocks it.
  Command-in-metadata, bad module containers and prototype keys are refused.
- LSCG command, broadcast and structured-beep routes; foreign targets; remote
  debug HTML; accepted commands continue to the actual upstream module.
- KikiLink communication with OwnerOnly / Block interactions; BCX metadata/read
  requests versus mutation requests; strict filtering explicitly overrides these.
- Native activity effects from denied senders stop; allowed activity passes.
- Native R132 clothing/restraint checks, blocked/limited items, body wardrobe,
  cosplay, owner/lover locks and friend/whitelist script-property distinction.
- Item, full-character and room-snapshot updates, empty valid appearance,
  CharacterID alias, relationship metadata, self and other-character updates.
- Game envelopes: target filtering, round progression, other targets, cards.
- Actual bundled Socket.IO before onAny/listeners, acknowledgements, frozen
  buffered events, current-permission replay, reconnects, late startup and
  cooperative method wrappers without repeated snapshot filtering.
- Bounded restore traffic, account/room cancellation, settings and private logs.
- 1,800 deterministic bounded malformed-wire cases produce no ingress exception.

Upstream fixtures execute actual selected BC server/client functions, five
historical Chaos Aura hooks, current AnimaFurta with its messaging library,
LSCG core/magic and R132 validators. Game state and mutation/network sinks are
synthetic. This does not test all effects in the entire upstream bundles.

RENDERER — HISTORICAL 0.4.0 BROWSER RESULTS

Two loopback HTTP origins supply real browser images with and without CORS.
The exact R132 mask/texture functions and exact game ModSDK are executed.
Deployed Echo clothing/activity and archived BCC mapping hooks are extracted;
BC Feather 2.0.0's exact alpha-mask patch remains installed in that chain.

The unprotected loader reproduces SecurityError on a real tainted canvas.
With KikiShield, a cached image retries once with anonymous CORS and becomes
origin-clean; a no-CORS host fails once and uses the fallback. Healthy layers,
mask-cache hits and BC Feather cache touches survive. Mutable canvas sources
are rechecked. Unrelated errors still propagate. The switch restores original
behavior when disabled. A mapper installed later remains compatible.
Guarded scenarios produce zero unhandled browser errors; no live image hosts
or game servers are contacted by the fixture.
